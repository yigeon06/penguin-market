# 🐧 Penguin Market (펭귄 마켓)

> **가상 자산 거래 및 소유권 관리 플랫폼**
> 
> 사용자가 가상 자산을 관리하고, 상점을 통해 펭귄을 분양 및 입양할 수 있는 백엔드 시스템입니다.
> 단순히 데이터를 저장하고 불러오는 것을 넘어, 실제 서비스처럼 자산 결제와 펭귄 소유권 이전이 동시에 일어나며, 이 과정에서 데이터가 어긋나지 않도록 안전하게 설계하고 구현하는 것을 최우선 목표로 삼았습니다.

<br>

## 🛠 Tech Stack
- **Language:** Java
- **Framework:** Spring Boot
- **Database:** MySQL, Spring Data JPA
- **Security:** BCrypt (Password Encryption)

<br>

## 💡 Key Features (주요 기능)

### 1. 안전한 회원 및 자산 관리 (Member)
- `BCrypt` 암호화 알고리즘을 적용하여 사용자 비밀번호를 안전하게 해시 처리 및 검증
- 이름, 생년월일, 전화번호를 활용한 본인 인증 및 아이디/비밀번호 찾기 기능
- 개인별 가상 자산(Assets) 보유 및 조회

### 2. 가상 자산 거래 시스템 (Store)
- 사용자가 희망 가격(Hope Price)을 설정하여 보유한 펭귄을 상점에 판매 등록
- 펭귄 입양 시, 구매자의 자산 차감 / 판매자의 자산 증가 / 펭귄의 소유권 이전 로직 수행

### 3. 데이터 기록 및 관리 (Penguin)
- 펭귄의 종, 서식지, 신체 정보(부리 길이, 몸무게 등) 상세 데이터 관리
- 특정 펭귄의 관찰 일지(Records) 작성 및 이력 추적 기능

<br>

## 🚀 Trouble Shooting & Technical Decisions (기술적 고민)

### 1. 거래 로직의 데이터 정합성 보장 (Transaction)
- **상황:** 펭귄을 입양하는 과정은 `1) 구매자 자산 차감`, `2) 판매자 자산 증가`, `3) 펭귄 소유권 변경`이라는 세 가지 작업이 동시에 발생합니다.
- **문제:** 네트워크 오류나 서버 다운 등으로 이 중 하나의 작업만 성공하고 나머지가 실패할 경우, 심각한 데이터 불일치(자산 증발 등)가 발생할 수 있습니다.
- **해결:** `@Transactional` 어노테이션을 활용하여 거래 과정을 하나의 논리적 작업 단위(트랜잭션)로 묶었습니다. 예외 발생 시 모든 작업을 롤백(Rollback) 처리하여 데이터의 원자성(Atomicity)과 정합성을 보장하도록 설계했습니다.

### 2. 예외 처리의 중앙 집중화
- **상황:** 자산 부족, 존재하지 않는 펭귄 조회, 비밀번호 불일치 등 다양한 비즈니스 예외 상황이 발생합니다.
- **해결:** `@ControllerAdvice` 또는 `GlobalExceptionHandler`를 활용하여 예외 처리 로직을 한 곳으로 모았습니다. 클라이언트에게는 상황에 맞는 명확한 에러 메시지와 HTTP 상태 코드를 반환하도록 구성하여 유지보수성을 높였습니다.
